# 棉花糖群聊激活与 worker 调度

作者：MengLei

## 插件用途

本插件负责天使/恶魔双平台下的普通 LLM worker 调度、命名呼叫判定，以及按当前群和当前 bot 保存的短时激活状态。

它不直接发送最终回复，不自己选择模型，不再 patch AstrBot Core 的 `GroupChatContext.need_active_reply`。provider、模型切换和回退链只使用 AstrBot 当前会话配置。

本文档是本仓库拍一拍（Poke）状态机的唯一叙述性行为合同主真源：项目 `AGENTS.md`、根 `README.md` 和 `astrbot_plugin_qqbot_features` 的 README 只保留边界摘要与阅读路由。修改拍一拍行为前必须先阅读本文档，并同步阅读机械回归测试 `tests/test_astrbot_topic_concentration_plugin.py`。

## 核心行为

- 直接 @ 当前 bot、引用当前 bot 或明确命名呼叫时，当前消息进入普通 LLM 链路，并把该 bot 在当前群激活 3 分钟。拍一拍当前 bot 走拍一拍状态机（见下文），非 MUTE 状态归一化为显式呼叫进入 LLM，仅实际发送可见文字回复才激活当前 bot。
- 本仓库必须关闭 AstrBot Core 的 `platform_settings.empty_mention_waiting` 和 `empty_mention_waiting_need_reply`。仅 @ 当前 bot、没有正文时，插件会归一化为无正文显式呼叫，由当前 provider 按 WebUI 人格生成类似“怎么了？有什么事情吗？”的自然短句，不进入 Core 的 60 秒等待分支。
- 非拍一拍的显式呼叫必须产生可见回复。用户明确要求“闭嘴、别说了、安静、退下”等同义意图时，模型先给出一句可见收尾，再附 `[[QQBOT_DEACTIVATE]]`；消息发送后当前群的当前 bot 反激活。拍一拍是否产生可见回复由模型决定，见下文拍一拍状态机。
- 非拍一拍显式呼叫首次模型结果为空或只有控制标记时，插件携带原会话 persona、上下文和当前消息，使用同一 provider/model 纠错重试一次；不切换独立 provider，不执行第二次工具调用。
- 拍一拍状态机按 `group_id + self_id` 维护 60 秒滚动拍击计数，单键历史有界，状态只存内存、插件重载即清空，不按发送者拆分计数。Poke 文案优先使用 `raw_info` 的实际灰条文本，缺失时回退为“昵称+摸了摸你的头”的统一表述。计数映射为无具体数字的定性重复程度：1-2 次平静（CALM）、3-5 次烦躁（ANNOYED）、6-8 次明显恼火（ARMED）、第 9 次起硬进入 30 秒 MUTE。每次注入提示要求模型结合 WebUI persona、会话上下文、当下氛围和可选当前时间组织回复，避免机械复用句式、意象以及时段/作息/放假/跑路笑点；不得向群友暴露内部等级、计数或窗口，回复不得报数字次数、第几次或内部状态。
- 非 MUTE 状态，同 `group_id + self_id` 同时只允许一个 Poke 进入 AI（AI 租约），租约结束后进入 3 秒冷却，节流期间到达的拍击仍计入计数。模型可返回 `[[QQBOT_SKIP_REPLY]]` 无视、调用请求级 `FunctionTool qqbot_poke_back` 反拍，或输出文字回复；ARMED 状态额外动态追加请求级 `FunctionTool qqbot_enable_poke_mute`，由模型自主决定是否提前开启 MUTE。反拍工具无参数；提前禁言工具只允许可选 `reason`，不接受用户指定目标或时长；两者目标都由代码固定为当前拍击者；同一事件内每个副作用最多尝试一次：handler 第一次进入后立即记录已尝试标记，后续工具调用统一返回 `already_attempted`，成功、普通失败、模型取消或 route/validation/claim 拒绝都不在同一 agent loop 重试；反拍失败只返回真实失败且该事件门禁仍消费，不谎称成功。提前禁言失败或模型取消立即释放全局 claim 且不得谎称成功，新的 Poke 事件在无冷却时重新由 AI 决策，只有禁言成功才进入 90 秒成功冷却。两个工具只在当前请求内临时存在。
- MUTE 的 30 秒内所有拍击不再调用 AI：插件本地重新校验当前事件与发送者后用 OneBot `set_group_ban` 锁定当前拍击者为禁言目标，时长随机 30-90 秒，同用户禁言成功后进入 90 秒冷却。无视、反拍和 MUTE 禁言都不激活当前 bot，只有实际发送可见文字回复后才激活当前群 3 分钟。
- 拍一拍按 `group_id + self_id` 维护拍一拍状态代际，每次进入 MUTE 递增；Poke 进入 AI 时捕获当前代际，两个请求级工具和 LLM 结果都按代际校验。进入 MUTE 会作废所有此前在途的 Poke AI 响应与请求级工具，MUTE 到期也不会恢复或补发这些旧请求。
- 仅 @ 的简短问句属于对呼叫动作的完整应答，回复风格守卫只在该事件标记下保留问句尾；其他普通回复仍清理追问式收尾。
- 同时 @ 天使和恶魔的普通聊天，两只都各自回复；每只只代表自己，不替另一个 bot 表态。
- 纯同时 @、`在吗`、`出来` 或 `说句话` 这类无实质正文场景，两只也各自短句应到，不转交、不追问用途。
- 普通文本包含“棉花糖”但没有明确 @ 时，先判断是不是在叫机器人。
- `棉花糖很好吃`、`草莓棉花糖在哪买` 这类食物、商品、物件或普通名词用法不回复。
- `棉花糖，帮我生成一张图片`、`棉花糖这个图片是哪个角色` 这类请求按群权重选一只回复。
- 模糊句只调用 AstrBot 当前会话 provider 做一次轻判定；失败时静默跳过，不新增独立 provider 或 fallback。
- 激活状态按 `group_id + self_id` 隔离；任何群友都能激活或反激活当前群中被明确叫到的 bot，不影响其他群、另一只 bot 或私聊。
- 激活窗口内，同群所有真人的普通消息都会成为当前 bot 主回复模型的候选消息。模型认为不值得插话时只返回 `[[QQBOT_SKIP_REPLY]]`，插件不发送消息、不续期，也不改变群 balance。
- 每个 bot 同时只允许一个普通候选进入 AstrBot 会话队列；候选等待超过 30 秒、激活窗口已过期或状态代际已变化时直接静默丢弃。provider 调用前失效的候选不再调用主回复模型，调用期间失效的候选不发送旧结果。显式 @、引用、命名呼叫和私聊不受该候选限制，仍按原规则排队处理；拍一拍不进入普通候选队列，按拍一拍状态机自身的 AI 租约与 3 秒冷却处理。
- 候选消息实际发送可见回复后，窗口重新续到 3 分钟，普通回复连续续期次数加一；显式呼叫续期时把该计数重置为零。
- 每次显式激活都会生成新的状态代际；延迟完成的旧候选回复或旧反激活结果不能覆盖后来重新 @、拍一拍或闭嘴建立的更新状态。
- 连续普通续期越多，注入给主模型的提示越强调提高沉默倾向、寻找自然收尾并返回 `[[QQBOT_DEACTIVATE]]`；连续续期达到 4 次后，遇到“问题解决、谢谢收尾、大家继续聊、不再需要你”等明确收尾语义时必须反激活，不能只跳过。反激活标记可以单独返回，也可以附在必要的简短收尾之后。
- `[[QQBOT_SKIP_REPLY]]` 和 `[[QQBOT_DEACTIVATE]]` 都是内部控制标记，会在发送和会话历史持久化前清理。
- 固定命令、生图、菜单、群务、下载、游戏存档等副作用入口只参与“唯一执行者选择”，交给 `astrbot_plugin_qqbot_features` 的固定命令 claim 保证只执行一次。

## 双 bot 边界

- 天使账号：`1443944862`。
- 恶魔账号：`2629227874`。
- 未激活时，同一条无目标命名呼叫按 canonical claim 只选择一个 worker；claim key 优先使用群号、发言者、当前纯文本、@ 目标、引用消息和时间桶，不依赖双平台可能不一致的 message_id。
- 激活窗口内的普通候选按当前 `self_id` 分开 claim；如果两只 bot 都在当前群处于激活状态，它们可以各自独立判断是否回复同一条普通消息。
- 同时 @ 天使和恶魔的普通聊天不使用唯一 worker claim，两只都可以各自回答。
- 未明确指定身份的普通命名呼叫按群 `balance` 概率选主处理者：balance 越大越偏向天使，越负越偏向恶魔，但概率会夹紧，不能变成必然选择。
- 点名谁就谁处理。只 @、引用或拍一拍其中一只时，即使该目标已有 LLM 请求在处理，也仍由目标自己处理，不由另一只代班；拍一拍按 `group_id + self_id` 的 AI 租约与 3 秒冷却在目标侧节流，节流期间拍击仍计数。
- 私聊消息永远由当前收到私聊的 bot 处理，不参与随机 worker 选择、跨 bot claim 或忙闲代班。

## 数据与安全边界

- 只维护内存中的群聊激活状态、busy 请求计数、message claim、群 balance、拍一拍 60 秒计数、请求级反拍/提前禁言工具 claim、禁言成功冷却和 MUTE 30 秒窗口状态。
- 重启或插件重载会清空上述全部内存状态；拍一拍计数和禁言状态不写入数据库或任何运行态文件。
- 反拍和提前禁言工具的目标由插件代码固定为当前拍击者，禁言时长在 30-90 秒内随机；模型不能指定群成员或时长。工具失败时不谎称成功，失败或取消立即释放 claim；MUTE 状态下的禁言由插件本地执行，完全不调用 AI。
- 不得把请求级反拍/提前禁言工具扩展成全局群管工具；它们只在当前 Poke 的 AI 租约内临时出现，目标固定为当前拍击者。MUTE 只影响当前群当前 bot 的 30 秒窗口，期间每个拍击只禁言触发它的当前发送者。
- 不读写用户资产、积分、游戏存档、私聊内容或公开群上下文快照。
- 不实现独立 provider 顺序、独立 fallback 或判定专用模型。
