# QQBot 连发、引用与断句

`qqbot_reply_guard` 为蓝铃主人私聊从接收时起收集两秒内的连续消息，并为 Planner 和原生 Replyer 展开本轮同会话的普通引用原文。准备上下文已经花掉的时间计入两秒窗口，新消息仍交给原有中断流程重新收集。

阶段回复与历史查阅指导放在原生 `[chat.reply_style]` 配置中。Planner 调用原生 `reply`，Replyer 根据完整人设、上下文和工具证据生成正文。
规划结果里写了要调用 reply、却没有真正调用工具，而且这条消息还没回复过时，补一次工具结果要求它立刻调用 reply。一条新消息只补一次。

规划回复时，插件按消息 ID 从已进入本轮的 QQ 消息元数据提供完整发送时间；生成正文时，通过同会话消息查询核对实际选中的回复目标。两处都同时提供当前处理时间及时间差，原始时间未取得时不拿当前时间代替。群聊触发频率、原有消息和图片不变。

蓝铃的普通 QQ 回复按自然段拆分。同一段内，较长正文可以从完整句末拆开。最多三条，短回复、代码块和列表整条发送。保留正文标点、中英文空格和原有段落。带附件的回复整条走原生发送。

原生 `reply` 发送首段后，插件依据成功回执，逐段通过 MaiBot 公开发送能力继续发送。发送失败或回执未知时结束本次分段。变更后运行仓库根目录的 `pytests/test_qqbot_short_reply.py`，用隔离发送出口核对正文、条数、引用、附件、发送时间及失败处理。

`qqbot_reply_timing` 继续负责按分段后的第一段抵扣本轮已耗时，以及首条公开消息成功前的新消息打断。后续分段和研究补充保持原速度。

将 `config.example.toml` 复制为本机 `config.toml` 后启用。连发与引用功能核对目标机器人 QQ、身份插件配置中的主人和真实私聊。分段适用于目标账号的群聊和私聊。
