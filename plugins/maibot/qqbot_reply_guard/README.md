# QQBot 连发、引用与断句

`qqbot_reply_guard` 为蓝铃主人私聊从接收时起收集两秒内的连续消息，并为 Planner 和原生 Replyer 展开本轮同会话的普通引用原文。准备上下文已经花掉的时间计入两秒窗口，新消息仍交给原有中断流程重新收集。

插件不再追加回复决策、搜索和记忆规则，也不在生成后调用另一个模型核对执行动作。阶段回复与历史查阅指导放在原生 `[chat.reply_style]` 配置中；联网能力由现有搜索插件提供。Planner 决策后调用原生 `reply`，原生 Replyer 结合完整人设、上下文和工具证据生成正文，再经过原有后处理分段与发送。
规划结果里写了要调用 reply、却没有真正调用工具，而且这条消息还没回复过时，补一次工具结果要求它立刻调用 reply。一条新消息只补一次。

规划回复时，插件按消息 ID 从已进入本轮的 QQ 消息元数据提供完整发送时间；生成正文时，通过同会话消息查询核对实际选中的回复目标。两处都同时提供当前处理时间及时间差，原始时间未取得时不拿当前时间代替。群聊触发频率、原有消息和图片不变。

蓝铃群聊和私聊通过公开 `maisaka.reply.before_post_process` Hook 将中文句间的半角空格或制表符转换为原生分段边界；预处理保留英文词组、数字及数字与单位之间的空格，以及成对引号或反引号内的空格。原生分段器处理正文后，每一段通过原生发送流程成为一条独立消息。后处理、错别字、段数配置、引用和附件沿用原生流程；插件关闭、目标账号不匹配、空回复或调用方已跳过后处理/禁用分段时不修改本次策略。

断句以日常聊天的自然停顿为准，一段对应一条独立消息，不为了减少气泡而合并正文。插件保持调用方的分段开关；只有提供并验证了效果更好的替代分段器，才可以关闭原生分段。变更后运行 `pytests/test_qqbot_short_reply.py`，在实际发送出口核对每条消息的完整内容、消息条数和停顿边界，并保留引用、附件、失败处理、打断行为及后续分段的发送间隔。

`qqbot_reply_timing` 继续负责按分段后的第一段抵扣本轮已耗时，以及首条公开消息成功前的新消息打断。后续分段和研究补充保持原速度。

将 `config.example.toml` 复制为本机 `config.toml` 后启用。连发与引用功能核对目标机器人 QQ、身份插件配置中的主人和真实私聊，不向群聊或其他私聊追加引用资料；中文停顿处理适用于目标账号的正常回复。插件不调用模型或发送接口。
