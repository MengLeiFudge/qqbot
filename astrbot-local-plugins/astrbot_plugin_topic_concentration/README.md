# 棉花糖主动接话门控

作者：MengLei

## 插件用途

本插件控制 AstrBot 普通群聊主动接话是否放行，并负责天使/恶魔双平台下普通 LLM worker 调度。

它不直接发送最终回复，也不自己选择模型。provider、模型切换和回退链只使用 AstrBot 当前会话配置。

## 核心行为

- 主动接话只处理普通群聊窗口；明确 @、引用当前 bot 和私聊只进入普通 LLM 调度，不进入主动接话判定。
- 保留 AstrBot Core 的主动回复开关、白名单和 method 门槛。
- 过滤另一个棉花糖发出的普通消息，避免双 bot 互相触发。
- 插件只做机械门控、批量话题归类、重复事件去重、同群 in-flight、群冷却、话题冷却、worker claim、上下文裁剪和接话意愿信号；是否应该接话由 LLM 基于群聊语境判断。
- 普通主动接话不再逐消息调用 LLM 判定；插件先收集普通群聊窗口，达到批量时间或消息数门槛后才把 AstrBot 原生群聊上下文节选、批量窗口和插件信号交给当前会话 provider 做一次话题归类。判定失败则静默跳过本批次，但 `should_reply=false`、topic、reason、耗时和 worker 必须写入 INFO 日志。
- 普通主动接话如果依赖图片、视频、表情、卡片或转发内容，但当前只有 `[图片]` 这类占位、没有可用文字描述或引用文本，会直接静默跳过，避免看不到图时猜图中物品、升级、价格、界面或报错。
- 明确出现“棉花糖”“棉花糖在吗”“呼叫棉花糖”或“棉花糖+明确请求”等命名呼叫时，插件按群权重选一个普通 LLM worker 并直接放行；同一用户短时间内紧接“在吗”等探活短句也继承这次呼叫，不依赖主动接话判定 provider。
- 主动接话放行时，本插件会把触发源消息的 `message_id` 和发言人 QQ 写入事件 extra；最终由 `astrbot_plugin_qqbot_features` 的回复风格守卫在第一条模型回复前补成“引用触发消息 + @触发发言人 + 空格 + 第一条消息正文”。
- 同一群已有主动接话判定正在等待 LLM 时，新的普通主动接话候选直接跳过；明确 @ 和私聊不受影响。
- 固定命令、生图、菜单、群务、下载、游戏存档等有副作用入口只参与“唯一执行者选择”，交给 `astrbot_plugin_qqbot_features` 的固定命令 claim 保证只执行一次。
- 普通 LLM 请求按两个 worker 调度：目标 bot 空闲时由目标处理；目标 bot 正在等待 LLM 返回时，只有技术、配置、报错、解释、查询、文档、代码等实质请求可由另一个 bot 用自己的身份代班/接力。短确认、仅标点或问号、标点/检讨/垄断类梗、`我要玩...工厂` 这类水群调侃不代班，避免另一只强行接梗或编造上下文。代班 worker 一开始处理，原目标 bot 就不得再完整回答原消息；代班回复公开后，原目标只允许做一句基于原消息和代班回复的实质短评论。
- 目标专属双子互动请求不代班，例如用户只 @ 恶魔说“和你妹妹抱抱”“叫你妹妹出来”“哄哄你妹妹”时，只能由恶魔自己处理；恶魔忙时天使不会接管完整回答，避免另一只截胡关系动作。

## 事件入口

本插件通过启动时 patch AstrBot 的 `GroupChatContext.need_active_reply` 接入主动接话判断；这是有意覆盖 Core 主动回复入口的实现，不是 WebUI 普通命令。插件只覆盖 `active_reply.method=possibility_reply` 的主动接话判定，其他 method 会回落 AstrBot Core 原逻辑。启动时会检查 `GroupChatContext.need_active_reply(self, event)` 签名，签名不兼容时不安装 patch 并记录 ERROR 日志。

同时用高优先级事件 handler 和 LLM request/response hook 管理普通 LLM worker busy/lease，因此管理端不会显示普通群聊命令。

## 双 bot 边界

- 天使和恶魔同群时，同一真人消息会被两个平台各收到一次。
- 本插件按 `group:<群号>` 共享窗口和冷却，避免同一消息双路判定。
- 本插件按 `group:<群号>` 共享 in-flight 门控，避免上游慢或超时时多个旧主动回复结果一起返回刷屏。
- 同一条普通 LLM 消息按 canonical claim 只选择一个 worker。claim key 优先使用群号、发言者、当前纯文本、@ 目标、引用消息和时间桶，不依赖双平台可能不一致的 message_id；引用消息优先使用引用正文摘要，只有没有引用正文时才退回平台 reply_id，避免同一条引用消息在天使/恶魔两路产生不同 claim。
- 同时 @ 天使和恶魔的普通聊天不使用唯一 worker claim，两只都可以各自回答；用户同时表达喜欢、感谢、夸奖或吐槽时，两只各自只代表自己回应，不替另一只接受、感谢或表态；同时 @ 双方的固定命令仍只选一只执行，另一只最多做短状态评论。
- 未明确指定身份的普通命名呼叫和固定命令按群 `balance` 概率选主处理者：balance 越大越偏向天使，越负越偏向恶魔，但概率会夹紧，不能变成必然选择。某只实际主处理后，balance 会向另一只回拉；代班短评论不计为主处理。
- worker busy 状态在 LLM request 时标记，在 LLM response 时释放，并有内存 lease 兜底，避免上游慢回复期间继续把新普通 LLM 请求压给同一个 bot。
- 引用其中一只 bot 的消息也会被纳入有效目标集合；例如引用恶魔只发“？？”时，目标忙也不会由天使接管。
- “和你妹妹/姐姐抱抱、贴贴、道歉、哄人、叫出来、转告”这类让被点名 bot 与另一只互动的请求是 worker 代班例外；目标忙时返回 `target_busy_no_delegation`，另一只不发完整答复。
- 代班提示只说明调度事实，不要求固定开场；回复不得反复说“妹妹/姐姐在忙”“我先接一下”“等她回来”，也不得编造另一个 bot 玩过、见过、能发截图或会回来处理。
- 另一个 bot 的普通输出不会触发当前 bot 主动接话。
- 明确 @ 当前 bot 仍走 AstrBot 直接请求链路，并在进入该链路前经过本插件 worker 调度。
- 私聊消息永远由当前收到私聊的 bot 处理，不参与随机 worker 选择、跨 bot claim 或忙闲代班。

## 数据与安全边界

- 只维护内存窗口、冷却和短期兴趣状态。
- 不读写用户资产、积分、游戏存档或私聊内容。
- 不实现独立 provider 顺序、独立 fallback 或判定专用模型。
